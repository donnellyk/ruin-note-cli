# Ruin Note CLI Spec
The goal is to build a CLI, written in go, for a notes app. The note taking system is loosely inspired by Zettelkasten.

In this spec, ‘document’, ‘file’, ‘note’, ‘card’ are used interchangeably to mean a markdown file the user saved via this CLI.

## Overall
Notes should be stored in a single folder as individual markdown files (*.md). The name ofthe file is explained [[/File Format]].  This folder is defined in `~/.config/ruin` file along with other default settings, in the user’s home directory. This folder will be referred to as the user’s vault.

In addition to markdown files of notes, the cli should maintain two additional metadata files in the user’s vault, stored within a folder `.ruin`
- .ruin/tags.yml
- .ruin/queries.yml

`tags.yml` contains a list of all tags used in all markdown files. This file should be updated when a new note is written by the CLI.

`queries.yml` contains named saved queries for searching through existing notes. The query format will be determined later

## File Format
Each note is a standard markdown file with frontmatter metadata, a markdown H1 title, and the content of the notes. The user can add any frontmatter they’d like outside of the CLI. This CLI will be maintained concerned with these frontmatter fields:
- uuid
- created
- updated
- tags
- inline-tags

Other frontmatter fields that will be used later, for additional features:
- parent — an parent card, for categorization and easy search, value will be a .md filename
- linked-cards — Other files that are referenced as wiki style links. Ex: [[Title]]
- order — An overall order, for sorting. 0 to very big number.

`uuid` is the unique ID of the note. This is to be generated by the CLI on first write. `global-tags` in a list of any tags present at the top of the document, under the title, or at the end of the document. `inline-tags` are any tags present within the content of the document.

A tag is a string that is preceded by a `#` 
Examples: `#foo, #bar, #date, #kevin, #2025/may`

The tool should also support tags with spaces by allowing the string to be surrounded by `#`
Examples: `#daily note, #vacation 2025#`

## CLI Commands
Commands should follow CLI UX best practices and naming conventions. 
### Log
`log` — Takes a string (implied to be markdown formatted) as input and saves to a markdown file
#### Options
- `-title` — The filename the file should be saved as
- `-h1` — Uses the first line of the file (after frontmatter, if present), if its an H1 header) as the filename
#### Other Logic
- If `-title` or `-h1` are not present, a timestamp should be the filename
- When saving the file, the frontmatter should be updated
  - if `uuid` is not present, one should be generated and used
  - `created` and `updated` dates should be written
  - `tags` and `inline-tags` should be parsed out of the document and stored, as noted in [[/File Format]]
#### Examples
Command:
```
$ ruin log -h1 /
# Run Log Update 3 /
#ruin #log /

Wrote the spec, but I need to #followup on the precise elements
```
Output:
File `Ruin Log Update 3.md` is written with contents
```
---
uuid: <valid UUID>
created: <valid datetime>
updated: <valid datetime>
tags: 
	- #ruin
	- #log
	- #followup
inline-tags:
	- #followup
---
# Run Log Update 3
#ruin #log

Wrote the spec, but I need to #followup on the precise elements
```

### Search
`search` — Searches files for substring or tag
#### Arguments
- `--bulk-export or -b` — A flag, command should return a single output with each note preceded by `%%%% <uuid> %%%%`. Frontmatter should be omitted. 
- `--first` or `-f` — A flag, command should return the contents of the first item of the search. Frontmatter should be omitted. 
- `--edit` or `-e` — A flag, Omits return value and opens content in $EDITOR instead. On save, [[/Update]] should be called to save to disk.
- `--sort` or `-s` — will sort the results, format of sorting argument to be defined later.
#### Other Logic 
- `-b, -f, -e` should be mutually exclusive, return an error if both are used.
- Search should be performant at possible. If the search only uses tags & dates, only look at frontmatter and not full text to save on memory and time.

#### Examples
Command:
```
$ ruin search #log && spec
```

### Update
`update` — Takes an edit bulk export (like from [[/Search]]), splits the contents, and saves to individual files
#### Options
- `--original`: The original bulk export, to compare against to understand which notes were moved and updated. Required.
- `--updated`: The updated text. Required.

#### Other Logic
- Deleted notes should be removed from disk. A note is considered 'deleted' if `%%%% <uuid> %%%%` appears in `original` but not `updated`.
- Metadata should be updated on save, just like `log`
### Doctor
`doctor` — Scans all markdown files in the vault and corrects/updates frontmatter as needed
#### Options
- `--dry-run` or `-n` — Show what would change without writing to disk
#### Other Logic
- Generate `uuid` if missing
- Reindex `tags` and `inline-tags` from document content
- Do NOT update `created` or `updated` timestamps
- Rebuild `.ruin/tags.yml` index from all notes
- Report summary of changes made (files updated, UUIDs generated, tags reindexed)

#### Examples
Command:
```
$ ruin doctor
```
Output:
```
Scanned 42 notes
  3 notes: generated missing UUID
  7 notes: reindexed tags
Updated .ruin/tags.yml
```

Command:
```
$ ruin doctor --dry-run
```
Output:
```
[dry-run] Would scan 42 notes
  3 notes: would generate missing UUID
  7 notes: would reindex tags
[dry-run] Would update .ruin/tags.yml
```
