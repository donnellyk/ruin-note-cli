# v0.4.0 Tag-Format Migration

This document describes the tag-format change in ruin v0.4.0 and what
downstream consumers need to do to keep working against the new contract.

## Summary

Stored tag values drop the `#` prefix. The change is invisible to users
who only type queries (`ruin search "#daily"` still works) and to anyone
reading note bodies in an editor (`#tag` and `#meeting notes#` are still
the body-text references). It is **visible** to:

- Anyone who reads frontmatter directly (Obsidian users, scripts that
  scan `tags:` arrays in `.md` files).
- Anyone who consumes JSON output (`ruin search --json`, `ruin pick
  --json`, `ruin tags --json`, `ruin embed eval --json`).
- Anyone who reads `.ruin/tags.yml` or `.ruin/titles.json`.

The `inline-tags:` frontmatter field is now configurable via the new
`tag_frontmatter` setting (default `true`). With the default, both
`tags:` and `inline-tags:` are written in stripped form. Setting
`tag_frontmatter=false` (or `RUIN_TAG_FRONTMATTER=false`) omits both —
useful for shared vaults where Obsidian is the primary tag-pane source
of truth. Either way `.ruin/titles.json` carries the per-note tag
mirror that ruin's matchers read. See
[`docs/obsidian-compatibility.md`](../obsidian-compatibility.md).

## Before / After

### Frontmatter (default: `tag_frontmatter=true`)

```diff
 ---
 uuid: 123
-tags:
-  - "#daily"
-  - "#work"
-inline-tags:
-  - "#followup"
-inherited-tags:
-  - "#project"
+tags:
+  - daily
+  - work
+inline-tags:
+  - followup
+inherited-tags:
+  - project
 ---
 # Daily Note
 #daily #work

 Catch up: #followup
```

`tags:`, `inline-tags:`, and `inherited-tags:` are all written in
stripped form (no `#`). Inline tags continue to be classified from
body content; they're mirrored in both frontmatter and
`.ruin/titles.json`.

### Frontmatter (`tag_frontmatter=false`)

```diff
 ---
 uuid: 123
-tags:
-  - "#daily"
-  - "#work"
-inline-tags:
-  - "#followup"
-inherited-tags:
-  - "#project"
+inherited-tags:
+  - project
 ---
 # Daily Note
 #daily #work

 Catch up: #followup
```

Both `tags:` and `inline-tags:` are omitted. `inherited-tags:` stays
in frontmatter as durable metadata (it isn't derivable from the note's
own body — it comes from ancestors). The body remains the source of
truth for own tags; `.ruin/titles.json` carries the per-note mirror
that ruin's matchers read.

### JSON output

```diff
-{"uuid": "...", "tags": ["#daily", "#work"], "inline_tags": ["#followup"]}
+{"uuid": "...", "tags": ["daily", "work"], "inline_tags": ["followup"]}
```

This applies to every `tags`, `inline_tags`, and `inherited_tags` array
in every JSON envelope (`ruin search --json`, `ruin pick --json`, `ruin
tags --json`, `ruin embed eval --json`, `ruin --bulk` exports).

### `.ruin/` indexes

All four index files gain a top-level `version: 2` key.

`.ruin/tags.yml` keys drop the `#`:

```diff
+version: 2
 tags:
-  - name: "#daily"
+  - name: daily
     count: 5
     scope: [global, inline]
```

`.ruin/titles.json` gains `tags`, `inline_tags`, `inherited_tags`
fields per entry (sorted, omitted when empty), plus the version key:

```json
{
  "version": 2,
  "titles": {
    "uuid-1": {
      "title": "Daily Note 1",
      "path": "/vault/Daily Note 1.md",
      "parent": "",
      "tags": ["daily", "work"],
      "inline_tags": ["followup"]
    }
  }
}
```

`queries.yml` and `parents.yml` add `version: 2` only — schema is
otherwise unchanged.

## Body markdown is unchanged

Tag references in note prose remain `#tag` (or `#meeting notes#` for
spaced tags). Anywhere ruin emits a tag back into body content
(`EnsureLinkTag`, `tags rename`, compose tag rendering), it uses
`pkg/notetext.BodyForm`, which re-adds the appropriate delimiters.

## CLI input is unchanged

Users continue to type `#tag` everywhere they do today:

- `ruin search "#daily"` — parser strips `#` before matching.
- `ruin pick "#followup"` — same.
- `ruin update tags=#a,#b` — parser accepts both forms; stores
  stripped.
- `ruin tags rename "#old" "#new"` — same.

## Migration

The first `ruin doctor` after upgrading to v0.4.0 detects pre-v0.4.0
notes (any `#`-prefixed entry in `tags:`, `inline-tags:`, or
`inherited-tags:`) and rewrites their frontmatter using
`(*Frontmatter).Serialize`. The Node-based serializer preserves
existing comments, key order, and quote styles for fields ruin doesn't
manage. The migration commits in a single auto-version commit:

```
ruin v0.4.0: tag-format migration (N notes)
```

Doctor's rewrite honors `tag_frontmatter`. With the default
(`tag_frontmatter=true`), legacy notes are rewritten in stripped form
with `tags:` and `inline-tags:` retained. With `tag_frontmatter=false`,
the migration commit additionally strips both `tags:` and
`inline-tags:` from every note in the same pass — the Obsidian-friendly
end state.

A second `ruin doctor` run is a no-op (idempotent). Use `ruin doctor
--dry-run` to preview the migration without writing.

If `ruin init` runs against an existing notes folder (e.g. an Obsidian
vault), it offers to invoke doctor on first run, which will perform the
migration as part of building the initial indexes. To migrate a vault
without ruin's own-tag mirror in one shot:

```bash
RUIN_TAG_FRONTMATTER=false ruin init ~/Obsidian-vault
```

### Recovery

The tag-format migration ships in a single git commit, so `git revert`
restores the pre-migration state. Downgrading the binary alone is not
supported: an older binary reading a v0.4.0 vault refuses with a clear
"vault written by newer ruin; binary must be upgraded" error (the
unknown `version: 2` in the indexes triggers the check).

## Downstream consumer checklist

Tools consuming ruin output need the following verifications:

- [ ] **JSON parsers**: tag arrays no longer have `#` prefixes. Strip
  `#` from cached comparison values, or normalize via
  `pkg/notetext.NormalizeStored` when importing the Go package.
- [ ] **Frontmatter scanners**: `tags:`, `inline-tags:`, and
  `inherited-tags:` arrays carry stored form when present. Vaults
  configured with `tag_frontmatter=false` omit `tags:` and
  `inline-tags:` entirely; `inherited-tags:` stays. Either way,
  `.ruin/titles.json` mirrors all three per entry.
- [ ] **`tags.yml` consumers**: keys are stripped. Queries grouped or
  filtered by `Name` need to drop the `#`.
- [ ] **`titles.json` consumers**: pick up `version`, `tags`,
  `inline_tags`, `inherited_tags` fields. Empty arrays are omitted.
- [ ] **Go consumers** importing `pkg/notetext`:
  - Replace remaining `notetext.NormalizeTag` calls with
    `notetext.NormalizeStored` (storage / comparison) or
    `notetext.BodyForm` (body emission).
  - `notetext.ClassifyTags` now returns stored form. Output fed back
    into note body text needs to be wrapped with `BodyForm` first.
- [ ] **Binary version check**: tools gating on a ruin version bump
  the requirement to v0.4.0 in the same release that adopts the new
  contract. Older binaries reading a v0.4.0 vault refuse to load.

## Spaced tags

`#meeting notes#` body syntax is preserved. Storage strips both
delimiters; round-trip is:

| Body form          | Stored form     | `BodyForm` round-trip |
|--------------------|-----------------|-----------------------|
| `#daily`           | `daily`         | `#daily`              |
| `#project/alpha`   | `project/alpha` | `#project/alpha`      |
| `#meeting notes#`  | `meeting notes` | `#meeting notes#`     |
| `#follow up#`      | `follow up`     | `#follow up#`         |

Obsidian doesn't natively support spaces in tags, so a stored
`meeting notes` value appears as a plain property value in Obsidian's
properties panel — same as `#meeting notes#` did pre-migration.

## Obsidian compatibility

For shared ruin/Obsidian vaults, set `tag_frontmatter=false` so ruin
defers to Obsidian's tag-pane convention (body tags only, no
frontmatter mirror). See [`docs/obsidian-compatibility.md`](../obsidian-compatibility.md)
for the recommended setup and what each tool reads, writes, and ignores.
